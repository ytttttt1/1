# RCS 容器绑定 / 解绑 Android App

内部试用版 1.2。员工只有一个仓位编号输入框、绑定和解绑按钮，扫码及所有可选参数输入框已从操作界面移除。

## 操作方式

1. 管理员首次进入设置，创建或输入本机管理员密码，填写现场实际 RCS 地址及固定容器类型（ctnrTyp），保存一次即可。没有预置万能密码，也没有把截图中的示例 IP 写入源码。
2. 员工输入仓位编号 stgBinCode，点击绑定或解绑，核对仓位与容器类型后确认。
3. RCS 明确返回成功后，程序只清空仓位编号；服务器地址和容器类型一直保存在本机，不会随操作清除。失败或超时不会清空仓位，便于核实。
4. 对结果未知的请求，先在 RCS 核实状态；重试使用原请求编号，不自动生成新请求。管理员可在受保护设置中修改地址、类型及密码，无需重新安装。

## 接口

依据 RCS-2000 V3.3 对外任务接口文档 3.1.8：

`POST /rcms/services/rest/hikRpcService/bindCtnrAndBin`

本版本发送 reqCode、reqTime、ctnrTyp、stgBinCode、indBind。容器类型和仓位号在解绑时均须提供以避免误操作。indBind 为字符串：1 绑定，0 解绑。此仓位专用流程不发送空容器号、地图位置，也不将仓位号猜测成容器号。若现场要求额外凭据或通过地图位置绑定，应在测试前确认接口要求，不要使用本版本直接处理不同业务。

## 连接故障

截图中的 failed to connect ... after 10000ms 是 TCP 连接失败，尚未收到 RCS 业务响应。应检查手机是否连接可访问 RCS 的内网、实际服务器 IP 和端口、服务监听与防火墙。不要把手机的来源 IP 当成服务器 IP，也不要在未确认网络与实际接口之前对生产仓位测试。超时不等于业务一定未执行。

## 编译与安装

GitHub Actions → Build Android APK → Run workflow。成功后在 Artifacts 下载 APK ZIP，解压得到 app-debug.apk。Android Gradle Plugin 8.6.1、Gradle 8.7、Java 17、SDK 35，最低 Android 6.0。

这是调试签名构建，不同云端 runner 的签名可能不同。只有 applicationId 相同、签名相同且 versionCode 递增才能可靠覆盖安装。签名不一致时不能直接覆盖；卸载会清除本机设置。正式部署应使用由公司保管的固定发布签名，不要将私钥或密码提交到仓库。修改本机配置不需要重新编译，修改程序逻辑仍需重新安装更新。

## 安全与验收

当前仓库应改为 Private。不要提交真实 Token、公司内部文档、生产凭据或签名私钥。管理员密码只保护本机设置，不替代 RCS 服务端权限。HTTP 明文仅用于受控内网；生产环境应由 RCS 侧实施访问控制与审计。此版本已添加请求参数单元测试，但仍须以实际 RCS 和测试仓位完成绑定、解绑及异常情况联调后才能正式使用。
